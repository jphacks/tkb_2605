# プロフィールとマスメイト

プロフィール・検索・関係の保存には[バックエンドPR #55](https://github.com/jphacks/tkb_2605/pull/55)のAPIが必要です。既存のセッション認証とCSRFを使います。

/profile/{user_id}はGET /api/users/{user_id}/profile/から名前・自己紹介・アイコン色・関係を取得します。投稿や通知のアイコンからも同じ画面へ移動します。肩・首・胸の形はホームと共通のBodyFrameです。

/profile/meは認証中の実IDへ移動します。/profile/me/editはGET /api/users/me/profile/で初期値を取得し、PATCHで名前（50文字まで）・自己紹介（160文字まで）・4種類のアイコン色をDBへ保存します。保存した内容はホーム・プロフィール・サイドバーにも反映し、再読み込み・再ログイン後も保持します。メールとパスワードの変更は対象外です。

/masmatesでは「マスメイト」と「ユーザーを探す」を切り替え、名前で検索できます。GET /api/users/?q=&masmates=true|false&limit=20&offset=0を使い、next_offsetで追加取得します。自分と無効なユーザーは一覧に含みません。

どちらかが「マスメイトになる」を押すとPUT /api/users/{user_id}/masmate/で関係を保存します。成功後だけ無効な「マスメイト」表示に変わり、相手から取得しても同じ関係になります。承認待ち・フォロー／フォロワーの区別・解除はありません。取得・保存に失敗した場合はエラーを表示し、保存済みと見なさず、書き込みを自動再送しません。

ログアウトやアカウント変更で表示キャッシュと進行中の取得を破棄します。別ユーザーの遅延応答や、保存前の取得結果が現在の表示を上書きしないようにします。DB上のプロフィールと関係は保持します。

ユーザー別投稿は既存のGET /api/users/{user_id}/posts/を使用します。投稿APIは固定応答のため、対象IDに一致しない応答はエラーとして表示します。ホームTLのマスメイトによる投稿絞り込みは投稿API側の追加対応が必要です。
