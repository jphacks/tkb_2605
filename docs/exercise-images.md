- リポジトリ: [U10-h/Muscle_Training_Private_ver](https://github.com/U10-h/Muscle_Training_Private_ver)
- ブランチ: `archive/repnote-sites-v1-v21-20261009`

- 元画像: `public/form-images/*.webp`、`public/equipment-images/*.svg`
- 種目と画像の対応: `app/form-image-index.json`、`app/form-gallery-data.json`
- 表示領域・寸法: `app/form-image-panels.json`、`app/form-image-dimensions.json`

- 配置先: `frontend/public/images/exercises/`（115点）、`frontend/public/images/equipment/`（49点）

Gitのmainには図解がないため、画像が保存されているアーカイブブランチを使用した。以前取得したSites保存版の16種目は、Git側の画像とSHA-256が一致することを確認済み。

## 表示と対応付け

種目選択・おすすめメニューで共通の `ExerciseVisual` / `ExerciseEquipment` を使用する。`exerciseMedia.json` は固定の種目UUIDをキーに、出典の種目ID、画像URL、寸法、表示範囲 `[x, y, width, height]`、SHA-256を記録する。

図解の1動作をCSSの表示範囲で切り抜き、人物と主要な器具を残す。元画像のバイト列は変更しない。一覧で種目を識別するためのサムネイルで、フォーム指導用の連続画像ではない。画像の読み込みに失敗しても、種目名と選択操作は維持する。ローカル配信なので元アプリへの通信・ログインは不要。

器具には具体的なマシンやアタッチメントの画像を対応付ける。「自重」は文字表示、「マシン」は集約フィルターとして残し、一覧の器具欄では具体名を表示する。ベンチ・ラック・ハンドルなども関連器具として検索できる。条件は「その器具を使う種目」であり、その器具だけで実施できる意味ではない。

## 接続と検証

追加種目を記録する前に、[種目マスターのDB同期](exercise-master.md#dbへの初期投入更新)を実行する。同期されていないIDは記録APIから404になる。バックエンドコード・APIの形式は変更しない。

`frontend/tests/exercise-media.test.ts` で全種目の画像対応、ローカルファイルの存在、SHA-256、切り抜き範囲、器具SVG、全部位の件数、代表的な器具の絞り込み対象を確認する。既存のカタログテストでUUID・関連参照・おすすめ・検索条件も検証する。
